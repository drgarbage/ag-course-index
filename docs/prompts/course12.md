# Course 12－課堂用提示詞整理

來源：`class12/slides/slide.md`。

## 開發前規劃與設計檢查

```text
1. 在你開始做之前，先跟我說明你打算怎麼設計這個功能，
   包含哪些部分是可以重複使用的，哪些是這次專屬的。
   我確認過後，你再開始執行。

2. 這份資料，以後如果我在別的功能也要用到，
   現在這樣的設計方式合適嗎？還是需要先調整？

3. 可以在原本的基礎上修改嗎？還是這次真的需要一個全新的做法？
   如果需要新的，請說明原因。
```

## Code Review

```text
請先以 code reviewer 的角度檢查本次修改。
請回報：
1. 是否符合原需求
2. 是否可能破壞既有功能
3. 是否有 API key、token、個資、敏感資料外洩風險
4. 是否有錯誤處理與 loading / empty state
5. 如果有高風險問題，請先列出，不要直接繼續擴充功能。
```

## 驗收方式

```text
請在完成修改後，先提出驗收方式：
1. 哪些資料格式不能壞
2. 哪個核心流程需要我手動走一次確認
3. 這次修改可能影響到哪些舊功能
4. 有沒有辦法用簡單的方式先自我檢查一次
```

## 跨頁共享狀態

```text
這個功能會跨多個畫面使用同一份資料。
請在實作前先規劃：
1. 哪些資料要集中管理，不要每個畫面各自取得
2. 畫面本身只負責呈現，資料處理放在畫面外面
3. 未來如果有類似資料，能不能重用同一套畫面邏輯
```

## 排程自動執行

```text
這件事我希望固定週期自動執行，不需要我每次手動觸發。
請幫我規劃：
1. 多久執行一次、由什麼條件觸發
2. 每次執行要做的固定步驟
3. 執行完後用什麼方式通知我或回報結果
4. 如果失敗了，要怎麼提醒我
```
