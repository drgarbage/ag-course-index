# Course 09－課堂用提示詞整理

來源：`class09/slides/slide.md`。

## 提案企劃顧問 System Prompt

```text
你是資深的提案企劃顧問，協助使用者撰寫給公部門的提案計畫書。

工作規則：
1. 開始撰寫前，必須先透過提問收集以下資訊，缺一不可：
   案由與背景、主辦機關與計畫名稱、服務對象、預算規模、
   執行期程、預期效益、我方優勢
2. 資訊不足時提出具體問題，一次最多問三題，不可自行假設
3. 資訊齊全後，先產出「大綱草案」給使用者確認，未經確認不得撰寫內文
4. 大綱格式參考以下範例：（附上公司慣用的計畫書綱目範例）
5. 使用者確認大綱後，每次撰寫一個章節，撰寫時參考已確認的大綱
   與前一章的內容摘要，維持文氣一致
6. 每章完成後停下來，等使用者說「繼續」才寫下一章
```

## 階段一：核心流程

```text
請進入 Plan Mode，先不要直接寫程式。

我想建立一個「AI 企劃寫手」React 應用程式，協助撰寫給公部門的
提案計畫書。第一階段只做核心流程：

1. Agent 對話介面：Agent 依照系統提示詞（另附）引導使用者——
   先訪談收集必要資訊，再產出大綱草案，使用者確認後逐章撰寫
2. 大綱確認機制：大綱以結構化方式呈現，使用者可調整並按下「鎖定大綱」
3. 逐章生成：每次只寫一章，寫完停下來等使用者驗收；
   也可由使用者選擇「連續寫完全部章節」
4. 文件以 Markdown 結構儲存（章節即標題層級）

請先幫我整理：使用者流程、SPEC.md 章節、資料結構、驗收清單。

限制：
- 遵循 git flow，此階段在 feature/stage1-core 分支開發
- 建立並持續維護 SPEC.md
- 未設定 API Key 時要有友善提示
```

## 階段二：Main View

```text
請開新的 feature branch 開發以下功能，完成後更新 SPEC.md：

把主畫面改造成 PDF 編輯器風格：
1. 中央為固定 A4 比例的分頁畫布，文件內容依 A4 高度自動分頁
2. 左欄顯示章節目錄（來自已鎖定的大綱），點擊可跳至該章
3. Agent 對話面板移至右側，可收合
4. 分頁畫布要接近列印時的實際樣貌（字級、邊界、頁碼）
```

## 階段三：檔案管理

```text
請開新的 feature branch 開發以下功能，完成後更新 SPEC.md：

加入文件管理：
1. 一個使用者可能同時進行多份計畫書：支援建立新文件、
   開啟舊檔、重新命名、刪除
2. 文件儲存於瀏覽器本機（localStorage 或 IndexedDB，由你評估建議）
3. 支援將文件匯出成檔案存放在本機，也支援從檔案匯入
4. 提供列印／另存 PDF 功能（以瀏覽器列印為基礎，只印文件內容）
```

## 階段四：版本歷程

```text
請開新的 feature branch 開發以下功能，完成後更新 SPEC.md：

加入版本歷程記錄：
1. 在文件最前方維護一份「修訂歷程」表格，欄位：版次、日期、
   修訂內容摘要、修訂人——符合官方文件的標準格式
2. 何時發布成新版本由使用者人工決定：使用者按下「發布新版本」時，
   輸入修訂摘要，系統將當前內容快照存檔並在修訂歷程新增一列
3. 可瀏覽歷史版本內容，可將文件還原至任一歷史版本
4. 未發布的編修屬於「工作中版本」，不進入修訂歷程
```

## 階段五：局部重寫

```text
請開新的 feature branch 開發以下功能，完成後更新 SPEC.md：

加入選取重寫機制：
1. 使用者在文件中選取一段文字後，出現「請 AI 重寫」操作
2. 使用者可附上重寫指示（例如：更精簡、口吻更正式、補充數據佐證）
3. AI 只重寫選取範圍，其他內容一字不動
4. 重寫結果以「對照預覽」呈現，使用者按「採用」才取代原文
```

## 階段六：人工共編

```text
請開新的 feature branch 開發以下功能，完成後更新 SPEC.md：

加入使用者自行編輯：
1. 文件內容可直接點擊編輯（章節標題與內文）
2. 人工編輯與 AI 編修共存：Agent 後續撰寫時，必須以文件的
   目前內容為準，不可覆蓋使用者的修改
3. 編輯操作即時存檔至工作中版本
```
